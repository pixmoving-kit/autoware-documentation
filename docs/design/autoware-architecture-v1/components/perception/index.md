# 感知组件设计

<a id="purpose-of-this-document"></a>

## 本文目的

本文概述感知组件开发中的高层设计策略、目标及其依据。希望所有开源开发者通过本文理解感知组件的设计理念、目标和约束，并顺利参与开发。

<a id="overview"></a>

## 概述

感知组件接收传感器、定位和地图组件的输入，添加语义信息（例如目标识别、障碍物分割、交通信号灯识别和占据栅格地图），再传递给规划组件。本组件设计遵循 Autoware 的总体理念，即[微自动驾驶概念](../../../autoware-concepts/index.md)。

<a id="goals-and-non-goals"></a>

## 目标与非目标

感知组件根据传感器采集的数据识别周围环境，获取足以支持自动驾驶的信息，例如动态目标、静态障碍物、盲区和交通信号信息。

整体设计强调[微自动驾驶架构](../../../autoware-concepts/index.md)：合理地模块化功能，清晰定义模块接口，从而实现高度可扩展的系统。在此背景下，感知组件的目标并非解决所有可想象的复杂场景（虽然希望支持基本场景），而是提供可按用户需求定制、便于开发附加功能的平台。

为明确设计理念，下面列出目标和非目标。

**目标：**

- 提供基本功能，使得能够定义简单的 ODD。
- 实现能够为每辆自动驾驶车辆提供感知功能的设计。
- 支持通过第三方组件扩展。
- 提供平台，使 Autoware 用户能够开发完整的功能与能力。
- 提供平台，使 Autoware 用户能够开发始终优于人类驾驶员的自动驾驶系统。
- 提供平台，使 Autoware 用户能够开发实现“100% 准确率”或“无错误识别”的自动驾驶系统。

**非目标：**

- 开发针对特定或有限 ODD 的专用感知组件架构。
- 实现完整的功能与能力。
- 超越人类驾驶员的识别能力。
- 实现“100% 准确率”或“无错误识别”。

<a id="high-level-architecture"></a>

## 高层架构

下图描述感知组件的高层架构。

![overall-perception-architecture](image/high-level-perception-diagram.drawio.svg)

感知组件由以下子组件组成：

- **目标识别**：识别当前帧中自车周围的动态目标，以及地图创建时不存在的目标，并预测其未来轨迹。包括：
  - 行人
  - 汽车
  - 卡车/公交车
  - 自行车
  - 摩托车
  - 动物
  - 交通锥
  - 道路杂物：掉落在道路上或飘浮在空中的纸板、油桶、垃圾桶、木材等
- **障碍物分割**：识别来自障碍物的点云，包括需要自车绕行或在其前方停车的动态目标和静态障碍物。
  - 包括：
    - 所有动态目标（如上所列）
    - 路缘石/隔离柱
    - 障碍栏
    - 树木
    - 墙壁/建筑物
  - 不包括：
    - 草
    - 水花
    - 烟雾/蒸汽
    - 报纸
    - 塑料袋
- **占据栅格地图**：检测盲区（无法获取信息、可能有动态目标突然出现的区域）。
- **交通信号灯识别**：识别交通信号灯颜色和箭头信号方向。

<a id="component-interface"></a>

## 组件接口

下文说明感知组件与其他组件之间的输入/输出概念。当前实现请参阅[感知组件接口](../../interfaces/components/perception.md)页面。

<a id="input-to-the-perception-component"></a>

### 感知组件的输入

- **来自传感器组件**：应提供环境的实时信息。
  - 相机图像：相机获取的图像数据。
  - 点云：LiDAR 获取的点云数据。
  - 雷达目标：雷达获取的目标数据。
- **来自定位组件**：应提供自车的实时信息。
  - 车辆运动信息：包含自车位置。
- **来自地图组件**：应提供环境静态信息的实时数据。
  - 矢量地图：包含环境的全部静态信息，包括车道区域信息。
  - 点云地图：包含静态点云地图，不应包含动态目标信息。
- **来自 API**：
  - V2X 信息：来自 V2X 模块的信息，例如交通信号信息。

<a id="output-from-the-perception-component"></a>

### 感知组件的输出

- **发送到规划组件**
  - 动态目标：提供行人和其他车辆等无法预先获知的目标的实时信息。
  - 障碍物分割：提供障碍物位置的实时信息，其表示比检测目标更基础。
  - 占据栅格地图：提供遮挡区域存在情况的实时信息。
  - 交通信号灯识别结果：实时提供各交通信号灯的当前状态。

<a id="supported-functions"></a>

## 支持的功能

| 功能 | 描述 | 要求 |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 基于 LiDAR DNN 的 3D 检测器 | 输入点云，检测汽车、卡车、公交车、行人和自行车等目标。 | - 点云 |
| 基于相机 DNN 的 2D 检测器 | 输入相机图像，在二维图像空间检测汽车、卡车、公交车、行人和自行车等目标。检测结果位于图像坐标中，不强制提供三维坐标信息。 | - 相机图像 |
| LiDAR 聚类 | 对点云进行聚类和形状估计，实现无标签目标检测。 | - 点云 |
| 半规则式检测器 | 结合图像和点云检测目标，由 LiDAR 聚类和基于相机 DNN 的 2D 检测器组成。 | - 相机 DNN 2D 检测器与 LiDAR 聚类的输出 |
| 基于雷达的 3D 检测器 | 输入雷达数据，检测动态 3D 目标。详情参阅[此文档](reference-implementations/radar-based-3d-detector/radar-based-3d-detector.md)。 | - 雷达数据 |
| 目标合并器 | 整合各种检测器的结果。 | - 检测目标 |
| 插值器 | 利用跟踪结果维持长期检测结果，使目标检测结果稳定。 | - 检测目标 <br> - 跟踪目标 |
| 跟踪 | 为检测结果分配 ID 并估计速度。 | - 检测目标 |
| 预测 | 根据地图形状与周围环境，预测动态目标的未来路径及其概率。 | - 跟踪目标 <br> - 矢量地图 |
| 障碍物分割 | 识别来自自车应避让障碍物的点云。 | - 点云 <br> - 点云地图 |
| 占据栅格地图 | 检测盲区（无法获取信息、可能有动态目标突然出现的区域）。 | - 点云 <br> - 点云地图 |
| 交通信号灯识别 | 检测交通信号灯的位置和状态。 | - 相机图像 <br> - 矢量地图 |
